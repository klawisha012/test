# Тикеты по ролям внутри срезов

Upstream `/to-tickets` делает каждый тикет вертикальным: один тикет проходит через все слои, и его можно показать сам по себе. Это удобно, когда всю работу делает один агент. У нас тикеты делают люди с разными ролями, поэтому единицей планирования остаётся срез, а публикуется он отдельными тикетами, по одному на роль. Тикеты среза делаются параллельно по общему контракту. В конце отдельный тикет проверки соединяет части и проверяет срез целиком. Ради параллельной работы мы отказались от того, чтобы каждый тикет можно было показать сам по себе: показать можно только срез целиком.

## Consequences

- Если в срезе больше одного тикета, на GitHub срез оформляется родительским issue. В нём записаны контракт и критерии приёмки, а тикеты среза являются его sub-issues. Срез из одного тикета публикуется как обычный тикет.
- Issue среза закрывается автоматически, когда закрыт последний из его тикетов. Обычно последним закрывается тикет проверки.
- При обновлении `to-tickets` из upstream правила нарезки нужно переносить вручную.
